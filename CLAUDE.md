## Product notes for this repo

Independent-clothing-brand discovery marketplace. Full decisions live in the user's memory file `brand-discovery-site`; the design brief is in `docs/claude-design-prompt.md`.

Key constraints:
- Not social-media first. The feed is secondary. Brand pages must not look like social profiles.
- Brand ("business") accounts go through a detailed onboarding; those fields are the source of truth for filters and AI natural-language search.
- **Every visitor is required to sign up** on first hit; `Personalize` (mounted in `layout.tsx`) reads `hydrated`, `account`, `onboarded` and redirects to `/signup` → `/onboarding` → their target. Open paths: `/login`, `/signup`, `/r/*`, `/design-system`.
- **One UI everywhere**, borrowed from the login screen: Instrument Serif on h1/h2 (weight 400, tracking -0.015em), squared inputs (`inputCls` = `rounded-sm` white + inset ink-rgba shadow), ink CTAs (`rounded-sm bg-ink py-[11px] text-[12.5px] font-semibold`), warm illustration on auth. The six-look palette system is gone. Onboarding still asks styles but only for recommendations (`styleOverlap` in `src/lib/looks.ts`) — never for theming.
- **Auth is real when configured.** `src/lib/supabase.ts` returns a browser client when `NEXT_PUBLIC_SUPABASE_URL` and `NEXT_PUBLIC_SUPABASE_ANON_KEY` are set; the store's `signUp`/`logIn`/`logOut` and `completeOnboarding` call Supabase then mirror to the local store, and fall back to the local demo account when the env vars are missing. Schema in `supabase/migrations/0001_init.sql` (profiles + style_tags + sizes + follows + saves, all with RLS and a `handle_new_user` trigger). Setup guide in `docs/supabase-setup.md`.
- Design language is **Kindred v2** (`docs/design/Kindred-v2.dc.html`, 2026-09-03 late): Plus Jakarta Sans, headlines 800 at −4% tracking, body 13/500, labels 10/600 uppercase wide. Palette: paper `#F6F4EF` page, cream `#EDE8DE` panels, sand `#DCD5C7`, ink `#121A24`, sage `#7C8C6F` accent, white cards. Cards 24px radius with a long soft shadow (`card` utility), pill controls, ink CTAs, soft-shadow white secondary buttons, no glass and no hairline-border cards. Use only the v2 names (paper/cream/sand/sand-2/sand-3/moss/ink/sage); the legacy aliases (offwhite/sky/peri/slate/navy/black) still exist in `globals.css` but no screen uses them any more. Brand pages are a storefront card (name, tagline, fact pills, Follow/Message, stats) beside the cover image, not a cover-plus-avatar profile. Base CSS lives in `@layer base` so utilities win. v1 `Kindred.dc.html` and the Geist/serif passes are superseded.
- Data model: `src/lib/data.ts` holds seed brands/products plus the option lists for onboarding (styles, moods, categories, materials, values, regions). `Brand` carries the onboarding fields that power filters and search. `src/lib/catalog.ts` is the pure engine: merge seed + user-created entities, promo pricing, `filterProducts`, feel-based `searchCatalog` (synonym expansion + price parsing), `dailyPick`. `src/lib/cart.ts` is the pure cart math (brand grouping, per-brand shipping, promo codes, points, gift cards; unit-tested and meant to run server-side later). `src/lib/store.tsx` is the client state (session, custom brands/products, promos, drops, orders, reviews, bag, follows, saved, alerts) persisted to localStorage under `kindred.v2`. Replace the store's persistence with a real DB when the backend lands; keep the catalog engine.
- `/api/search` calls Claude (`claude-opus-5`, structured output) to turn a feeling into intent when `ANTHROPIC_API_KEY` is set; the client falls back to `searchCatalog` otherwise. Set the key in Vercel env to switch it on.
- Also in the store: brand posts (Following feed + brand Posts tab), shopper↔brand message threads (`/messages`), custom lookbooks built in the dashboard (frames with image URL + one hotspot), waitlist for sold-out pieces, price alerts, drop reminders, a derived `notifications` list shown from the nav bell, rewards points (1/$1), a `featured` brand that takes the home hero (dashboard "Feature on home"), CSV product import, verification requests, gift cards (`/gift`: buy → `KIND-XXXX-XXXX` code, redeem in bag alongside promo codes and points; balance decrements on `placeOrder`), per-product view counts (`views` keyed by product slug as well as brand slug) feeding the dashboard Audience tab, and `recent` product views shown as a Recently viewed row on Discover. Pre-orders: `Product.preorder` (ISO ship date) flips the CTA to “Pre-order · ships …” and tags the card; set from the dashboard product form. Referrals: `/r/[code]` applies `referredBy` (+200 points once); the account page shows the shopper's own code (`slugify(name)`). Images are plain URLs rendered with `<img>` (no next/image; hosts are arbitrary).
- Business accounts: `/sell` is the 7-step brand onboarding; it creates a Brand, switches the session to role `brand`, and lands on `/dashboard` where products, promos, drops, orders, and settings are managed. Everything a brand enters shows up immediately in Explore filters, search, and their public page.
- Routes: `/` discover (For you / Following / Drops, daily pick), `/explore` (real filters, `?q=` feel search, `?cat=`), `/brand/[slug]`, `/product/[slug]` (reviews, price alerts), `/bag` (promo codes), `/checkout` (places orders), `/lookbook/[slug]`, `/gift`, `/account`, `/sell` (brand onboarding), `/dashboard` (seller: Overview, Audience, Products, Promos, Drops, Lookbooks, Orders, Messages, Settings), `/onboarding` (shopper), `/design-system`. Search is an overlay (`SearchOverlay.tsx`), bag is a drawer (`BagDrawer.tsx`).
- **SEO.** `src/lib/seo.ts` owns every meta tag. `SITE` (name, tagline, description, url, ogImage, keywords, twitter), `seo({title, description, path, image, keywords, type, noIndex})` returns a full Next `Metadata` object with canonical, OG, Twitter, robots and Googlebot rules; per-entity helpers `productSeo`, `brandSeo`, `lookbookSeo`; JSON-LD builders `orgJsonLd`, `siteJsonLd` (WebSite + SearchAction), `productJsonLd`, `brandJsonLd`, `breadcrumbJsonLd`; `ROUTE_META` + `routeSeo` for static routes. Client pages import their metadata via a server shim `page.tsx` that renders a client `Client<Name>.tsx` child — never `use client` on a file that exports `metadata`. Layout emits Organization + WebSite JSON-LD in `<head>`; dynamic routes emit Product/Brand + Breadcrumb JSON-LD alongside their client view. `robots.ts` allows GPTBot, Google-Extended, ClaudeBot, PerplexityBot and disallows account/bag/checkout/messages/dashboard/onboarding/login/signup/r/api. `sitemap.ts` includes home + static + brand + product + lookbook URLs with change-frequency and priority.
- Stack: Next.js App Router, TypeScript, Tailwind v4, pnpm, deploy on Vercel.

Rules learned the hard way:
- Toggle handlers must use functional `setState` updates; rapid clicks otherwise overwrite each other.
- Keep global element rules inside `@layer base`; an unlayered `a { color: inherit }` silently beats every Tailwind color utility on links.
- Never gate hydration on `requestAnimationFrame`; it does not fire in background tabs. Use `setTimeout(…, 0)`.
- Hover must never grow a shadow. The `lift` utility rises 3px, shifts the card to cream and eases the image; the user rejected shadow-based hover.
- Tests: `pnpm check` (lint + typecheck + vitest) and `pnpm test:e2e` (Playwright, desktop + Pixel 7). Next 16 allows one dev server per project, so with `pnpm dev` running use `E2E_BASE_URL=http://localhost:3000 pnpm test:e2e`. The e2e reset script wipes `kindred.v2` once per test via a sessionStorage flag; wiping on every navigation breaks multi-page flows.
- The React compiler lint forbids `Date.now()` in render; use `useNow()` from `src/components/Countdown.tsx`.
